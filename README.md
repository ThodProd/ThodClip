# ThodClip

Постоянная история буфера обмена и архив скриншотов для **ThodHUB** на Windows x64.

ThodClip запоминает всё, что вы копируете, пока он запущен: текст, файлы и изображения. Записи хранятся в SQLite внутри папки данных ThodHUB, поэтому переживают перезапуск, обновление модуля и очистку системной истории Windows. Любую запись можно скопировать обратно одной кнопкой, закрепить или удалить.

Скриншоты из стандартных папок Windows и Snipping Tool автоматически копируются в архив. Даже если удалить оригинал из `Изображения\Снимки экрана` или с рабочего стола, архивная копия останется доступной.

## Возможности

- История текста, файлов и изображений без ограничения по времени (настраиваемый лимит записей).
- Скопировать обратно текст, файлы или изображение; для файлов можно скопировать как сами файлы, так и список путей.
- Поиск по всей истории и фильтры: текст, файлы, картинки, закреплённые.
- Календарь копирования: количество записей за каждый день, переход к нужному дню и группировка истории по дням.
- Длинные тексты свёрнуты в карточке; кнопка «Раскрыть» загружает полный текст.
- Закрепление важных записей — они не удаляются при очистке и ограничении истории.
- Архив скриншотов с превью, полноэкранным просмотром, копированием, сохранением и удалением.
- Импорт уже существующих скриншотов из стандартных папок.
- Настройки повторов, лимитов хранения и исключений Windows.
- Светлая и тёмная темы, адаптация к узкому окну ThodHUB.

## Честные ограничения

- **ThodClip не заменяет Win+V.** Стороннее приложение не может встроиться в системное меню истории Windows. ThodClip ведёт собственную историю и копирует записи обратно через свой интерфейс.
- **Запись работает, пока запущен ThodHUB.** Embedded-worker запускается при первом открытии ThodClip и живёт до закрытия хаба. Автозапуска, службы или фонового трея нет — это требование контракта ThodHUB.
- Форматирование (RTF/HTML) не сохраняется: текст записывается как обычный Unicode-текст.
- Очень длинный текст обрезается настраиваемым лимитом (по умолчанию 1 МБ, максимум 2 МБ).
- В архив попадают изображения, похожие на скриншоты: из Snipping Tool, размером с экран или лежащие в папках со снимками. Обычные картинки остаются только в истории буфера.
- Защищённые данные с флагами `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory=0` или `CanUploadToCloudClipboard=0` не записываются, пока включена настройка исключений.
- Нет облачной синхронизации и шифрования базы: данные лежат локально в папке ThodHUB.

## Установка

1. Откройте ThodHUB → Каталог.
2. Найдите **ThodClip** и нажмите «Установить».
3. Откройте ThodClip. Запись начнётся сразу; состояние видно в правом верхнем углу.

Обновления ставятся через ThodHUB. Предыдущая версия сохраняется хабом для отката, данные при этом не мигрируют и не удаляются.

## Данные и приватность

Все данные находятся только в каталоге данных ThodHUB (`THODHUB_DATA_DIR`), вне папки версии:

```
clip.db                 база SQLite
config.json             настройки
blobs/                  оригиналы изображений из буфера
thumbs/                 превью изображений
shots/orig/             архивные копии скриншотов
shots/thumb/            превью скриншотов
```

- Ничего не отправляется в сеть.
- В репозиторий не попадают пользовательские базы, настройки, токены или скриншоты.
- Для резервной копии закройте ThodHUB и скопируйте всю папку данных: в режиме WAL отдельный `clip.db` без `-wal` может быть неполным.
- При удалении модуля через ThodHUB данные сохраняются, если не отмечен пункт удаления данных.

### Очистка

- «Очистить историю буфера» в настройках удаляет записи ThodClip; закреплённые можно сохранить.
- «Очистить архив скриншотов» в настройках удаляет только архивные копии, оригиналы в пользовательских папках не трогает.
- Системный буфер обмена и история Windows (Win+V) не изменяются.

## Права модуля

| Право | Зачем |
|---|---|
| `worker` | Запуск `ThodClip.Worker.exe`, доступ к буферу, файлам и SQLite. |
| `files.export` | «Сохранить как…» для скриншотов и изображений (лимит ThodHUB — 8 МБ). |

Модуль не запрашивает `clipboard.write`: копирование выполняет worker через нативный буфер Windows, поэтому работают изображения и списки файлов, а не только текст.

## Сборка

Требования: Windows x64, .NET SDK 10.0.4xx, PowerShell 7+ (или Windows PowerShell 5.1), Node.js не обязателен.

```powershell
dotnet test .\tests\ThodClip.Tests\ThodClip.Tests.csproj -c Release
.\scripts\build.ps1 -Version 1.0.0
```

`scripts/build.ps1`:

1. Публикует self-contained worker под `win-x64`.
2. Копирует UI, `manifest.json`, README и лицензии.
3. Вызывает `scripts/package-module.ps1` из контракта ThodHUB.
4. Проверяет SHA-256 и размер ZIP против `thodhub-release.json`.

Результат: `artifacts/thodclip-<version>-win-x64.zip` и `artifacts/thodhub-release.json`.

Для локальной проверки без упаковки:

```powershell
.\scripts\build.ps1 -Version 1.0.0 -SkipPackage
```

### CI и релиз

GitHub Actions (`.github/workflows/release.yml`) запускается на тег `hub-vX.Y.Z`, собирает проект на `windows-latest`, прогоняет тесты, проверяет совпадение версии с тегом и создаёт **stable** GitHub Release с ZIP и `thodhub-release.json`. Существующие релизы и ассеты не перезаписываются: для изменений нужен новый тег и новая версия.

## Тесты

```powershell
dotnet test .\tests\ThodClip.Tests\ThodClip.Tests.csproj -c Release
```

Покрыты: дедупликация, поиск, закрепление, удаление, очистка, лимиты, календарные счётчики, фильтр по дню, обрезка больших текстов, архивация и дедупликация скриншотов, импорт, настройки.

Ручной протокол worker:

```powershell
$env:THODHUB_DATA_DIR = "$env:TEMP\thodclip-test"
$env:THODCLIP_SCREENSHOT_ONLY = "1"
$env:THODCLIP_SCREENSHOT_DIRS = "$env:TEMP\thodclip-test\shots"
'{"jsonrpc":"2.0","id":"1","method":"status"}' | .\src\ThodClip.Worker\bin\Release\net10.0-windows\ThodClip.Worker.exe
```
